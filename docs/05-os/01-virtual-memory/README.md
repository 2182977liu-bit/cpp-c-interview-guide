## 1. 为什么程序不能直接使用物理内存

假设两个程序都直接使用物理地址，程序 A 把数据放在 `0x10000`，程序 B 也把数据放在 `0x10000`，它们就会互相覆盖。任何一个程序的野指针还可能破坏别的程序，甚至破坏操作系统。

虚拟内存给每个进程提供一套独立的地址视图。程序看到的是**虚拟地址**，真正访问内存条时使用的是**物理地址**，中间由 MMU 和页表完成转换。

这套机制主要带来四种能力：

| 能力 | 通俗解释 | 典型例子 |
|---|---|---|
| 隔离 | 一个进程不能随便读写另一个进程 | 空指针通常只让当前进程收到 SIGSEGV |
| 保护 | 同一块内存可分别限制读、写、执行 | 代码页可读可执行，但通常不可写 |
| 受控共享 | 不同虚拟地址可映射到同一物理页 | 共享库、共享内存、fork 后的写时复制 |
| 按需使用 | 不必一开始就把全部数据装进物理内存 | 文件映射、惰性分配、swap 换入 |

先纠正一个常见误解：**虚拟内存不等于 swap，也不等于“拿磁盘冒充内存”。** 即使系统完全关闭 swap，虚拟地址、页表、MMU、权限隔离和按需分页仍然在工作。

## 2. 先分清页、页框、虚拟地址与物理地址

分页把虚拟地址空间和物理内存分别切成固定大小的小块：

- **页（page）**：虚拟地址空间中的一块。
- **页框（page frame）**：物理内存中的一块。
- 一个页和一个页框大小相同，但一个是虚拟概念，一个是物理概念。
- **页表项（PTE）**：描述虚拟页到物理页框的映射及权限等信息。
- **MMU**：CPU 中负责地址转换和访问权限检查的硬件。
- **VMA**：Linux 描述一段连续虚拟地址区域的内核对象，例如一段堆、栈或 mmap 映射；VMA 不是页表本身。

以常见的 4 KiB 普通页为例：

```text
页大小       = 4096 字节 = 2^12 字节
页内偏移位数 = 12 位
虚拟页号     = 虚拟地址 >> 12
页内偏移     = 虚拟地址 & 0xFFF
```

如果某个虚拟页已经映射到物理页框，可以概念性地写成：

```text
物理地址 = (物理页框号 << 12) | 页内偏移
```

这里的公式用于理解结构，不代表所有架构的 PTE 都把信息按同样方式排列，也不代表用户程序可以自行读取物理页框号。

### 2.1 虚拟连续不等于物理连续

程序看到的一段连续缓冲区：

```text
虚拟地址：  页 100  -> 页 101  -> 页 102  -> 页 103
                 |          |          |          |
物理页框：     页框 8     页框 91     页框 3      页框 56
```

只要每一页都建立正确映射，程序就可以像访问连续数组一样访问它们。物理页框是否相邻，普通用户程序通常不需要关心。

但设备 DMA、某些驱动或内核内存分配可能需要物理连续内存，那属于另一层问题，不能用“虚拟地址连续”来证明物理连续。

## 3. 一次虚拟地址转换是怎样完成的

以最简单的单级模型说明：

1. CPU 执行一条 load/store 指令，得到虚拟地址。
2. MMU 先查 TLB；若命中且权限满足，直接得到物理地址。
3. TLB 未命中时，硬件页表遍历器或软件按架构规则查询页表。
4. 若映射有效，取得物理页框号，加上页内偏移得到物理地址。
5. MMU 检查读、写、执行等权限，通过后真正访问内存。
6. 若页不在物理内存或权限不满足，则触发缺页异常，由操作系统进一步处理。

完整路径可以概括为：

```text
虚拟地址
   |
   v
查 TLB --命中且权限通过--> 物理地址 --> 访问内存
   |
 未命中
   v
遍历页表 --有效且权限通过--> 填充/更新 TLB --> 访问内存
   |
 不存在、未驻留或权限不满足
   v
缺页异常 --> 内核判断：修复后返回，或向进程发送信号
```

注意：**页表保存在内存中，MMU 是硬件，页表内容由操作系统维护。** 不能回答成“操作系统为每一次内存访问都执行一段转换函数”；正常路径主要由硬件完成，否则每次 load/store 都进内核会慢得无法接受。

## 4. 为什么需要多级页表

### 4.1 单级页表的问题

假设虚拟地址有 48 位，普通页为 4 KiB，那么虚拟页数量是：

```text
2^48 / 2^12 = 2^36 个页
```

若单级页表每项按 8 字节估算，仅一张覆盖整个空间的页表就需要：

```text
2^36 × 8 字节 = 2^39 字节 = 512 GiB
```

而真实进程的地址空间通常非常稀疏：代码、堆、共享库和栈分散在不同区域，中间存在大片未使用空间。给这些空洞也分配 PTE 会造成巨大浪费。

### 4.2 多级页表如何节省空间

多级页表把虚拟页号再拆成若干级索引。只有某一级下面确实存在映射时，才需要分配下一级页表。

以常见的 x86-64 四级分页、48 位虚拟地址、4 KiB 页为例：

```text
47        39 38        30 29        21 20        12 11         0
+------------+------------+------------+------------+------------+
| PGD 索引 9 | PUD 索引 9 | PMD 索引 9 | PTE 索引 9 | 页内偏移 12 |
+------------+------------+------------+------------+------------+
```

每一级索引 9 位，所以一张表有 `2^9 = 512` 项。每项 8 字节时，一张表正好是 `512 × 8 = 4096` 字节。

Linux 通用页表模型写作：

```text
PGD -> P4D -> PUD -> PMD -> PTE -> 物理页
```

其中：

| 名称 | 含义 |
|---|---|
| PGD | Page Global Directory，页全局目录 |
| P4D | 为五级分页引入的一层 |
| PUD | Page Upper Directory，页上级目录 |
| PMD | Page Middle Directory，页中间目录 |
| PTE | 最底层页表，其表项映射普通页 |

在四级 x86-64 上，P4D 会被折叠，不是硬件一定再走一次完整查表。支持五级分页的 x86-64 使用 57 位虚拟地址，在前面再增加 9 位索引。

**不要把“48 位”“四级”“4 KiB”说成所有 CPU 的永恒规则。** 页大小、虚拟地址宽度和级数都与架构、内核配置及硬件能力有关。

### 4.3 多级页表的空间账怎么算

假设一个进程只映射了一个 4 KiB 页，在四级模型下，除了最终数据页，通常需要沿路径准备四级页表。若每级表都占 4 KiB，这条稀疏路径的页表本身可占约 16 KiB。

所以多级页表不是“任何情况下都比单级省”：它主要赢在**巨大而稀疏的地址空间**。当大量地址都被密集映射时，页表总开销仍然可观。

## 5. 页表项除了物理页号还记录什么

PTE 不只是“虚拟页号对应物理页框号”的一条记录，还包含状态与权限。不同架构的名称和位布局不同，常见语义包括：

| 标志或字段 | 作用 | 与什么现象有关 |
|---|---|---|
| Present | 当前映射是否可直接用于访问 | 不在物理内存时可能触发缺页 |
| Read/Write | 是否允许写入 | 写只读映射可能触发异常 |
| User/Supervisor | 用户态还是特权态可访问 | 防止用户程序直接读内核页 |
| Execute/NX | 是否允许取指执行 | 限制把栈或数据页当代码执行 |
| Accessed | 页面是否被访问过 | 为回收策略提供参考 |
| Dirty | 页面是否被写过 | 回收脏页前可能需要写回 |
| 物理页框信息 | 指向实际页框或大页区域 | 形成最终物理地址 |

权限检查与“页是否存在”是两类条件。例如，写只读页时，页可能明明已经在物理内存中，仍然会因为权限不满足而进入异常处理。

用户程序也不应依赖某个 PTE 位的精确位置。跨架构的内核代码会封装这些差异，普通应用通过 `mmap`、`mprotect` 等接口表达需求。

## 6. TLB：地址转换的高速缓存

### 6.1 为什么需要 TLB

四级页表如果每次都要完整遍历，一次数据访问可能附带多次页表读取，开销很大。TLB 是 MMU 中缓存“虚拟页到物理页转换及权限”的小型高速结构。

| 情况 | 大致路径 | 是否等于缺页 |
|---|---|---|
| TLB 命中 | 直接得到转换结果并检查权限 | 否 |
| TLB 未命中，页表有效 | 遍历页表，取得映射 | 否 |
| 页表显示未驻留或需内核处理 | 进入缺页异常处理 | 是 |
| 地址或权限非法 | 异常处理后可能发送 SIGSEGV | 不是普通性能事件 |

最重要的一句话：**TLB miss 只说明转换缓存没命中，不代表页不在物理内存，更不代表程序一定出错。**

### 6.2 局部性为什么影响 TLB

假设顺序访问 4 MiB 数据：

- 使用 4 KiB 页，需要覆盖 1024 个虚拟页。
- 若使用 2 MiB 大页，只需覆盖 2 个大页。

在访问工作集很大、页又很分散时，有限容量的 TLB 更容易发生替换。大页减少同等数据量所需的映射数量，因此可能降低 TLB 压力和页表遍历成本。

### 6.3 进程切换与 TLB

不同进程的同一虚拟地址可以对应不同物理页，因此切换地址空间时必须保证不会误用旧映射。硬件和内核可通过刷新、地址空间标识符等机制处理，具体方式依赖架构。

当内核修改或解除映射时，还要让相关 CPU 上可能存在的旧 TLB 项失效，这类跨核维护常被称为 **TLB shootdown**。它说明页表更新不只是“改一个内存变量”，还涉及缓存一致性与并发。

## 7. 缺页异常：不一定是程序出错

教材常把 page fault 翻译成“缺页中断”，更严格地说它是由当前指令触发的**同步异常**。CPU 保存现场并转入内核处理，而不是像外部设备中断那样随时异步到来。

### 7.1 内核收到缺页异常后做什么

可以把处理过程简化为：

1. 取得出错虚拟地址、访问类型和权限信息。
2. 在当前进程地址空间中查找该地址所属的 VMA。
3. 判断这次访问是否有合法修复路径。
4. 若合法，分配页框、读取文件、执行写时复制或建立页表映射。
5. 更新页表和必要的状态，返回后重新执行原指令。
6. 若非法，则向当前线程发送相应信号；典型非法访问会导致 SIGSEGV。

“重新执行原指令”很重要：调用 mmap 或 malloc 时，内核可以先建立虚拟区域；真正读写到某页时才触发异常，修复完成后，应用通常感觉不到这次异常。

### 7.2 常见缺页原因

| 原因 | 内核可能采取的动作 | 是否说明程序有 bug |
|---|---|---|
| 匿名页首次访问 | 建立零页映射或分配物理页 | 通常不是 |
| 文件页尚未进入内存 | 从 backing store 读入并建立映射 | 通常不是 |
| 页面被换出到 swap | 发起换入 I/O | 通常不是，但可能有性能问题 |
| fork 后写共享的私有页 | 复制页并改为可写，即 COW | 通常不是 |
| 写只读区域 | 合法 COW 则复制，否则报错 | 视映射约定而定 |
| 访问未映射地址 | 无法修复，通常发送 SIGSEGV | 很可能是 |
| 超出栈允许增长范围 | 无法继续扩展 | 很可能是栈溢出或限制触发 |

### 7.3 minor fault 与 major fault

Linux 的 `getrusage` 接口提供：

- `ru_minflt`：不需要 I/O 活动即可处理的缺页次数。
- `ru_majflt`：处理过程中需要 I/O 活动的缺页次数。

可以粗略记成“次缺页不一定慢，主缺页涉及 I/O 往往更慢”，但不要进一步简化成“minor 只分配内存、major 只从 swap 读”。文件映射和页缓存同样会影响分类，最终以内核统计语义为准。

## 8. 按需分页、零页与写时复制

### 8.1 malloc/mmap 成功，不等于物理页已经全部到位

虚拟内存允许先建立“这段地址可以用”的记账信息，再在首次访问时落实物理资源，这叫**惰性分配或按需分页**。

这样做有两个好处：

1. 申请很大但实际只使用很小一部分时，不为未触及页面提前付出全部成本。
2. 把分配和首次访问的成本分散开，但实时程序因此需要额外处理缺页延迟。

### 8.2 匿名页为什么读出来是零

匿名映射没有普通文件作为后备。对新匿名私有页的读访问，Linux 可以让它先映射到共享的只读零页；真正写入时，再分配独立物理页并建立可写映射。

这既保证新匿名页面不会泄露其他进程的旧数据，也避免为“只申请、只读、从不写”的区域立即分配大量独立页面。

### 8.3 fork 的写时复制

fork 创建子进程时，不必立刻复制父进程所有内存页。父子先共享原有物理页，并把需要按 COW 处理的私有可写页暂时改为只读。

某一方随后写入时：

1. CPU 因写保护触发异常。
2. 内核识别这是合法 COW，而不是普通非法写。
3. 在需要时分配新页并复制内容，修改写入方页表权限。
4. 返回后重新执行写指令。

因此，fork 后父子看到相同内容，不代表以后写入仍共享同一份数据；**共享的是尚未被写开的页面，语义上仍是各自独立的私有内存。**

## 9. 实验一：观察页大小与虚拟地址拆分

下面程序读取系统普通页大小，并把几个虚拟地址拆成“虚拟页号 + 页内偏移”。它不会、也不能靠这个计算得到真实物理地址。

保存为 `page_address.c`：

```c
#include <inttypes.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

static int global_value = 42;  /* 已初始化全局变量，通常位于可执行文件的数据区域。 */

/* 打印一个虚拟地址对应的页号和页内偏移，不读取物理地址。 */
static void show_address(const char *name, const void *address, uintptr_t page_size)
{
    uintptr_t value = (uintptr_t)address;
    uintptr_t vpn = value / page_size;
    uintptr_t offset = value % page_size;

    printf("%-12s 地址=%p 虚拟页号=%" PRIuPTR " 页内偏移=0x%" PRIxPTR "\n",
           name, address, vpn, offset);
}

int main(void)
{
    long value = sysconf(_SC_PAGESIZE);
    if (value <= 0) {
        perror("sysconf");
        return EXIT_FAILURE;
    }

    uintptr_t page_size = (uintptr_t)value;
    printf("普通页大小：%ld 字节\n", value);

    /* 普通页大小应为 2 的幂；不满足时不继续做位运算示例。 */
    if ((page_size & (page_size - 1)) != 0) {
        fprintf(stderr, "当前页大小不是 2 的幂，停止示例。\n");
        return EXIT_FAILURE;
    }

    int local_value = 7;  /* 局部变量，通常位于当前线程栈。 */
    int *heap_value = malloc(sizeof(*heap_value));
    if (heap_value == NULL) {
        perror("malloc");
        return EXIT_FAILURE;
    }
    *heap_value = 99;

    show_address("全局变量", &global_value, page_size);
    show_address("栈变量", &local_value, page_size);
    show_address("堆变量", heap_value, page_size);

    free(heap_value);
    return EXIT_SUCCESS;
}
```

编译运行：

```bash
gcc -std=c11 -Wall -Wextra -O2 page_address.c -o page_address
./page_address
```

你会看到不同运行之间的地址可能变化，这与 ASLR、链接方式和运行环境有关。即使两次运行的虚拟地址相同，也不能推出它们对应同一个物理页。

还可以只读查看当前环境的普通页大小：

```bash
getconf PAGE_SIZE
```

## 10. 实验二：观察按需分页与缺页计数

下面程序用 `mmap` 建立 64 MiB 匿名私有映射，先记录资源统计，再逐页写一个字节，最后比较缺页计数。

保存为 `demand_paging.c`：

```c
#include <stdio.h>
#include <stdlib.h>
#include <sys/mman.h>
#include <sys/resource.h>
#include <unistd.h>

/* 读取当前进程资源统计，失败时直接终止示例。 */
static struct rusage read_usage(void)
{
    struct rusage usage;
    if (getrusage(RUSAGE_SELF, &usage) != 0) {
        perror("getrusage");
        exit(EXIT_FAILURE);
    }
    return usage;
}

int main(void)
{
    const size_t bytes = 64u * 1024u * 1024u;  /* 示例只申请 64 MiB 虚拟区域。 */
    long page_value = sysconf(_SC_PAGESIZE);
    if (page_value <= 0) {
        perror("sysconf");
        return EXIT_FAILURE;
    }
    size_t page_size = (size_t)page_value;
    size_t pages = bytes / page_size;

    struct rusage before = read_usage();

    /* 建立匿名私有映射；返回成功不等于每一页都已分配独立物理页。 */
    unsigned char *area = mmap(NULL, bytes, PROT_READ | PROT_WRITE,
                               MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (area == MAP_FAILED) {
        perror("mmap");
        return EXIT_FAILURE;
    }

    printf("映射完成：%zu 字节，共 %zu 个普通页\n", bytes, pages);

    /* 每页写一个字节，迫使这些页真正可写并驻留；不要只读未触及区域。 */
    for (size_t i = 0; i < pages; ++i) {
        area[i * page_size] = (unsigned char)i;
    }

    /* 再读一次并打印校验和，让写入后的数据确实参与计算。 */
    unsigned long long checksum = 0;
    for (size_t i = 0; i < pages; ++i) {
        checksum += area[i * page_size];
    }

    struct rusage after = read_usage();
    printf("校验和：%llu\n", checksum);
    printf("次缺页增量：%ld\n", after.ru_minflt - before.ru_minflt);
    printf("主缺页增量：%ld\n", after.ru_majflt - before.ru_majflt);
    printf("历史最大 RSS：%ld KiB\n", after.ru_maxrss);

    if (munmap(area, bytes) != 0) {
        perror("munmap");
        return EXIT_FAILURE;
    }
    return EXIT_SUCCESS;
}
```

编译运行：

```bash
gcc -std=c11 -Wall -Wextra -O2 demand_paging.c -o demand_paging
./demand_paging
```

通常会观察到次缺页明显增加，但**不要要求增量精确等于页数**，原因包括：

- 差值统计的是整个进程在此期间的缺页，不只这一处循环。
- 运行环境、内存回收、内核实现和编译器优化都会影响结果。
- `ru_maxrss` 是历史最大驻留集，不是这块映射当前独占的物理内存。
- 本示例没有创建 swap 压力，主缺页增量完全可能为 0。

若要观察文件映射的 I/O，应另外设计可控文件、页缓存与测试流程，不能根据这个匿名映射示例推断磁盘性能。

## 11. 大页、局部性与性能

普通页、大页并不是“越小越省”或“越大越快”的简单关系。

| 对比项 | 4 KiB 普通页 | 2 MiB/1 GiB 等大页 |
|---|---|---|
| 同等数据量所需映射数 | 多 | 少 |
| TLB 覆盖范围 | 较小 | 较大 |
| 页表遍历和页表项数量 | 通常更多 | 通常更少 |
| 细粒度回收与共享 | 灵活 | 粒度较粗 |
| 内部浪费风险 | 较小 | 只使用少量数据时可能浪费较多 |
| 分配条件 | 普通页较易满足 | 连续大页可能受碎片影响 |

Linux 常见两类大页机制：

- **HugeTLB**：通常需要预留或显式管理大页池，应用按相应接口使用。
- **THP（透明大页）**：内核尝试对符合条件的普通映射透明地使用大页，配置与合并策略会影响行为。

面试回答性能时不要只说“大页提高 TLB 命中率”就结束。还要补一句：**收益取决于工作集和访问模式，大页也会带来内存浪费、分配失败、合并与回收成本，必须实测。**

访问局部性同样重要。按页顺序访问与在大范围随机跳转，即使读取相同总字节数，TLB、缓存和缺页表现也可能完全不同。

## 12. Linux 中如何做只读观察

### 12.1 查看进程虚拟内存区域

```bash
# 查看当前 Shell 启动的 cat 进程自身映射；self 在打开时指向实际读者。
cat /proc/self/maps

# 查看指定进程；把 PID 换成真实进程号，并注意权限。
cat /proc/PID/maps
```

`/proc/pid/maps` 每行主要字段为：

```text
address           perms offset  dev   inode       pathname
```

| 字段 | 含义 |
|---|---|
| address | 这段 VMA 的起止虚拟地址 |
| perms | 读、写、执行及 shared/private 属性 |
| offset | 文件映射在后备文件中的偏移 |
| dev | 设备主次号 |
| inode | 关联 inode；匿名区域通常为 0 |
| pathname | 后备文件或 `[heap]`、`[stack]` 等伪名称 |

`rw-p` 中的 `p` 常表示私有、写时复制语义，`s` 表示共享。maps 展示的是 VMA，不是把每个 PTE 都打印出来。

### 12.2 VSZ、RSS 与真实占用不能画等号

| 指标 | 大致含义 | 不能直接说明什么 |
|---|---|---|
| VSZ/虚拟大小 | 进程虚拟地址区域总量 | 不等于当前实际占用这么多物理内存 |
| RSS/驻留集 | 当前统计到的驻留页面集合 | 不等于进程独占物理内存 |
| PSS | 将共享页按比例分摊后的统计 | 也不是简单的“独占 malloc 大小” |
| swap 使用量 | 部分页面换出的规模 | 不等于整个虚拟内存大小 |

共享库页可能同时计入多个进程的 RSS；尚未触及的匿名映射可能计入虚拟大小，却没有等量独立物理页。因此看到 VSZ 很大，不应立刻判定发生内存泄漏。

## 13. 底层原理串联与踩坑清单

### 13.1 把一次访问串起来

以“程序向 malloc 返回的一块内存写数据”为例，完整理解路径可以是：

1. 分配器管理用户态空闲块，必要时通过 brk 或 mmap 扩展虚拟区域。
2. CPU 使用虚拟地址执行写指令。
3. TLB 命中则快速转换；未命中则查页表。
4. 如果页表尚未建立可写映射，进入缺页异常。
5. 内核确认地址属于合法 VMA，并判断是匿名首次写、COW 还是其他情况。
6. 内核分配或选择页框，更新 PTE，处理必要的 TLB 状态。
7. 返回用户态重新执行写指令，最终访问物理内存。

这套流程把**分配器、VMA、页表、MMU、TLB、缺页异常和物理页框**串成了一条线，比孤立背定义更容易应对追问。

### 13.2 踩坑清单

1. **把虚拟内存等同于 swap。** swap 只是页面换出的一种后备机制，不是虚拟内存存在的前提。
2. **把页和页框混为一谈。** 页属于虚拟地址空间，页框属于物理内存。
3. **认为虚拟连续就是物理连续。** 普通虚拟缓冲区可能对应离散页框。
4. **以为每次地址转换都进内核。** 正常转换由 MMU/TLB 和页表遍历完成，异常才进入内核处理。
5. **把 TLB miss 等同于缺页。** TLB 未命中后仍可能查到有效驻留映射。
6. **把所有缺页都当成程序崩溃。** 首次访问、文件加载和 COW 都是正常缺页来源。
7. **把段错误理解为物理内存不够。** 常见 SIGSEGV 是地址未映射或权限非法，不是简单 OOM。
8. **认为 malloc 成功就已拿到等量独占物理页。** 按需分页和 overcommit 使二者不能画等号。
9. **认为 64 位指针就能使用 2^64 地址。** 实际可用虚拟地址宽度受架构与系统限制。
10. **机械背诵四级页表。** Linux 通用模型有五级，具体架构可折叠某些层，页大小也会变化。
11. **认为多级页表没有代价。** 它节省稀疏空间，但增加遍历层级，稀疏映射自身也需要多张表。
12. **认为 RSS 就是进程独占内存。** 共享页、未触及页和统计口径都会影响判断。
13. **把大页当成无成本加速开关。** 它可能改善 TLB，也会带来碎片、浪费和回收成本。
14. **在普通用户程序里试图从虚拟地址直接推算物理地址。** 物理映射由内核和硬件管理，不应依赖未授权或架构相关的细节。
15. **为了消除缺页而随意锁内存。** mlock 等操作需要权限、资源和容量评估，可能影响整个系统，不是普通性能调优的第一步。

## 14. 面试真题

### Q1：什么是虚拟内存？它解决了什么问题？

**三句话答案：** 虚拟内存让每个进程使用独立虚拟地址，再由 MMU 和页表映射到物理地址。它提供进程隔离、访问权限、受控共享和按需分页等能力。虚拟内存不等于 swap，关闭 swap 后这些基本机制仍然存在。

### Q2：页和页框有什么区别？为什么常见页内偏移是 12 位？

**三句话答案：** 页是虚拟地址空间的块，页框是物理内存中同样大小的块。4 KiB 页等于 4096 字节，即 2^12 字节，所以低 12 位表示页内偏移。12 位只对应 4 KiB 页，换成其他页大小，偏移位数也会改变。

### Q3：虚拟地址如何转换成物理地址？

**三句话答案：** MMU 先查 TLB，命中且权限满足就直接得到物理页框信息。未命中时按页表层级索引查询页表，最后把物理页框基址与页内偏移组合。映射未驻留、需要特殊处理或权限不满足时，会触发缺页异常交给内核判断。

### Q4：为什么要用多级页表？

**三句话答案：** 单级页表要覆盖整个虚拟地址空间，大量未使用区域也会消耗表项空间。多级页表只在下层存在映射时分配对应页表，适合巨大而稀疏的地址空间。代价是 TLB 未命中时可能需要多级遍历，因此还需要 TLB 和大页等优化。

### Q5：x86-64 四级页表的 48 位地址怎样拆分？

**三句话答案：** 在 4 KiB 普通页场景下，低 12 位是页内偏移，其余 36 位分成四段，每段 9 位。四段依次索引 PGD、PUD、PMD 和最底层页表，每张 512 项、每项 8 字节时一张表正好 4 KiB。Linux 通用模型还有 P4D，但四级硬件上该层会折叠，五级分页则使用更宽的虚拟地址。

### Q6：TLB 是什么？TLB miss 会发生缺页吗？

**三句话答案：** TLB 是缓存虚拟页到物理页转换及权限信息的硬件结构，用于避免频繁完整遍历页表。TLB miss 只表示缓存没有该转换，页表仍可能指向已经驻留的有效页面。只有页表状态或权限需要内核异常处理时，才进入缺页路径，两者不能画等号。

### Q7：什么是缺页异常？处理流程是什么？

**三句话答案：** 缺页异常是 CPU 访问内存时因映射未驻留或权限等条件无法满足而进入内核的同步异常。内核根据出错地址和访问类型查找 VMA，合法时分配、读入或复制页面并更新页表，然后重新执行原指令。无法修复的非法访问通常会向当前线程发送 SIGSEGV 等信号。

### Q8：minor fault 和 major fault 有什么区别？

**三句话答案：** Linux 的 getrusage 统计中，minor fault 不需要 I/O 活动即可完成处理，major fault 的处理需要 I/O 活动。文件页、页缓存、匿名页和 swap 都可能影响实际分类与延迟。不能简单把 minor 等同于首次 malloc、把 major 只等同于 swap 换入。

### Q9：为什么 malloc 或 mmap 返回成功，物理内存却没有立即增加同样多？

**三句话答案：** 按需分页允许先建立虚拟区域和相应内核记账信息，首次访问时再落实页面。匿名私有读页还可能先映射到共享零页，写入时才分配独立可写页。此外 overcommit、共享映射和统计口径都会让虚拟大小与物理占用不同。

### Q10：fork 的写时复制是怎样利用缺页异常实现的？

**三句话答案：** fork 后父子先共享适合的物理页，并把私有可写页按 COW 需要设置写保护。某一方写入时触发异常，内核识别合法 COW 后分配或调整页面、复制内容并恢复写权限。这样只有真正发生写入的页面才需要分离，降低 fork 的初始成本。

### Q11：为什么大页可能提升性能？有什么代价？

**三句话答案：** 大页用较少映射覆盖同样数据量，能减少 TLB 压力、页表项数量和部分遍历成本。它适合部分大工作集负载，但收益取决于访问模式。大页还可能造成内部浪费、连续内存分配困难以及额外合并和回收成本，因此必须结合指标实测。

### Q12：VSZ 很大是否说明进程内存泄漏？RSS 是否等于独占内存？

**三句话答案：** VSZ 主要描述虚拟地址区域总量，其中可能包含尚未触及或共享的映射，不能据此直接认定泄漏。RSS 统计驻留页面，但共享库等页面可能同时算进多个进程，不等于独占物理内存。排障还应结合 PSS、匿名页变化、分配器信息和持续趋势，而不是只看一个瞬时数字。

### Q13：修改页表后为什么还要处理 TLB？

**三句话答案：** TLB 中可能仍保存旧转换，如果只改页表，CPU 可能继续使用过期权限或物理页映射。内核需要使相关 TLB 项失效，在多核场景还可能向其他 CPU 发起同步处理。具体刷新范围和地址空间标识符优化依赖硬件架构与内核实现。
